# ai-coding-harness

一套跨 Claude Code / Codex 的 AI 编码约束,**从「AI 反复在哪翻车」倒推出来的**,不是从「好代码应该怎样」推出来的。

规则正文只有 62 行,其余全是让规则**不依赖模型记得**的机制。

只覆盖**短任务**(一次修复、一个小功能)。长任务的失败模式(目标漂移、上下文压缩后遗忘早期结论、重复造已写过的轮子)一条都没解决。

完整的设计推导在 **[DESIGN.md](DESIGN.md)**(692 行,含一次 codex 批判性复审)——
README 只说结论,「为什么是这几条、哪些方案被否掉了、为什么否」在那里。

---

## 一、它治的是什么病

「失败模式」= AI 写代码时**反复出现的、有固定形状的错法**。不是泛指 bug,是那种见过很多次、能提前描述出形状的错误。

**整个仓库按这张表组织。** 每条规则、每个检查都必须挂在某个 F 编号下 —— 挂不上的就是没证明必要性,不该存在。

| 编号 | 失败模式 | 长什么样 |
|---|---|---|
| **F1** | **只修给出的那一个 case** | 你报「这句话路由错了」,它加一行 `if "退款" in query`。原始输入过了,换个说法照样错 |
| **F2** | **把失败伪装成成功** | 接口挂了,`except` 里 `return {}`;或生产路径上留 `return self._mock_evaluation()`。调用方分辨不出这是真结果还是失败,错误往下游飘 |
| **F3** | **只敢加不敢删** | 改完留一个 `build_payload_v2`,旧的还在。跑几轮满仓库 `_v2` / `_legacy`,文件越滚越长 |
| **F4** | **重复造已有的轮子** | 不查现有实现就新写一个,结构几乎相同、只是改了变量名 |
| **F5** | **卡住了还在瞎试** | 同一个问题试第 5 种改法,每次都说「这次应该对了」 |
| **F6** | **伪造验证结论** | 「已验证,功能正常」——一条命令没跑。或者测试挂了就改断言去迁就实现 |
| **F7** | **凭记忆用第三方 API** | 按训练数据里的签名调用,和你 lock 的版本对不上 |
| **F8** | **做你没要求的事** | 顺手重构、顺手加个「更完善的」错误处理、顺手改配置 |
| **F9** | **陷在自己的上下文里出不来** | 从头做到尾的那一个 agent,做完时正处在最确信自己做对了的状态。让它自查,它会把新增分支解释成「真实的不同情况」;让它造验证变体,那些变体是照着它刚写的修复的形状造的 —— 自证 |

F1 是核心,F3/F4 算它的下游。**F1 也是唯一一个静态检查基本抓不到的** —— 见第六节。
F9 是**元失败模式**:它让其他八条的自查全部失效,所以它的解法不是再加一条规则,是换个 agent。

## 二、怎么解决的:三层

| 层 | 是什么 | 保证强度 | 常驻上下文成本 |
|---|---|---|---|
| **规则层** | `AGENTS.md` 62 行 | 靠模型自觉,**零保证** | **每轮都付费** |
| **机制层** | `check.py` / ruff / hook / skill | 不依赖模型记得,但只认得出代码外形 | 0 |
| **验证层** | 变体 + 邻近反例,实际跑 | **唯一能证明修复泛化的** | 0(写在规则层里的一条要求) |

**核心约束:只有 AGENTS.md 那 62 行是每轮对话都要付的钱。**
所以凡是能被脚本查、能被 hook 触发、能被 skill 承载的,**都不许写进 AGENTS.md**。
这条约束决定了整个目录的形状 —— 不是「规则越全越好」,是「常驻的越少越好」。

**决定一条约束放哪一层,问三个问题**(这是设计文档里的判据,新增规则时照用):

1. 模型**有没有能力**做到?没有 → 写规则也没用,得换机制。
2. 有能力的话,**会不会可靠地做**?不会 → 下沉到机制层,别指望提醒。
3. 做没做,**能不能验证**?不能 → 这条规则等于不存在,写了反而有害(见第九节末)。

**一个反面做法:不要靠「让 AI 更啰嗦」解决。** 要求它每次汇报都自查一遍清单,只会得到更长的假汇报 —— F6 正是这么来的。

## 三、失败模式 → 拦在哪

**这张表是加新规则时的落点。** 空着的格子就是已知缺口,不是待办。

| | AGENTS.md 条款 | check.py 规则 | 其他 |
|---|---|---|---|
| **F1** 单 case 补丁 | 禁止对自由文本做关键词/正则判断猜意图;禁止硬编码具体用户输入;**先说清失败输入属于哪一类** | `keyword-match` | code-simplifier skill;**验证层(变体+反例)才是真正拦它的** |
| **F2** 假成功 | 失败不得被转换成看似成功的结果(不变量) | `fake-success`、`prod-mock` | — |
| **F3** 只加不删 | 确认无调用方就直接删,不留 shim;不接受「保留旧的以防万一」 | `version-suffix`、`file-too-long` | — |
| **F4** 重复造轮子 | 新写函数前说明现有相近实现为何不可复用 | `dup-func` | — |
| **F5** 卡住瞎试 | 连续 3 次修复失败就停,报告卡点 | — | — |
| **F6** 伪造验证 | 没实际执行过命令不许说「已验证」;汇报必须带范围;改测试断言须有独立证据 | — | Stop hook 会拦一次,逼它处理未验证项 |
| **F7** API 幻觉 | 用第三方 API 前先确认**已安装版本**的实际签名 | — | — |
| **F8** 范围扩张 | 不实现我没要求的功能;做了没要求的事必须说 | — | diff review |
| **F9** 陷在自己上下文 | **验证者不该是开发者本人**;只给审查者「原始需求 + git diff」 | — | 干净上下文的 subagent。Claude Code 用 Task,Codex 用 `collaboration.spawn_agent` |

F5–F8 没有自动检查 —— **这是结构性的,不是没来得及做**。它们是关于「过程」的,静态分析看不到过程。
F9 也没有,但原因不同:它有机制(换 agent),缺的是「有没有真的换」这件事本身不可验证。

## 四、装法

```bash
# 1. 规则正文
cp AGENTS.md CLAUDE.md            <你的项目>/

# 2. 检查脚本(单文件、零依赖、只用标准库)
mkdir -p <你的项目>/scripts && cp scripts/check.py <你的项目>/scripts/

# 3. 平台 hook(可选,但这是「不依赖模型记得」的关键)
cp -r .claude/                    <你的项目>/
cp -r .codex/                     <你的项目>/

# 4. ruff 配置 —— 不要整份复制,把 pyproject.ruff.toml 的内容合并进已有的 pyproject.toml
# 5. pre-commit(可选)
cp .pre-commit-config.yaml        <你的项目>/

echo ".check-hits.log" >> <你的项目>/.gitignore
```

Codex 首次加载项目 hook 时会要求审查。确认项目可信后,在 CLI 里运行 `/hooks`,
检查命令内容并信任当前定义;hook 变化后需要重新审查。

装完自测:

```bash
python selftest/run.py
# OK — 6 条规则全部触发,邻近反例零误报,豁免机制正常
```

**`CLAUDE.md` 必须是指向 `AGENTS.md` 的一行 `@AGENTS.md`,不能反过来** ——
Codex **不认** `@` 导入语法。内容放 `AGENTS.md`(两边都读),`CLAUDE.md` 只做指针。
反着写的话 Codex 会读到零条规则。

| 文件 | 作用 | 常驻成本 |
|---|---|---|
| `AGENTS.md` | 唯一规则正文,62 行 | **每轮都付费** |
| `CLAUDE.md` | 一行 `@AGENTS.md` | ~0 |
| `scripts/check.py` | 6 条 AST 检查,全是警告 | 0 |
| `pyproject.ruff.toml` | ruff 配置片段,替代手写风格指南 | 0 |
| `.claude/settings.json` | PostToolUse + Stop hook | 0 |
| `.codex/hooks.json` | Codex CLI 的 PostToolUse + Stop hook | 0 |
| `.claude/skills/code-simplifier/` | 语义级审查,description 写成触发条件 | 0(只有一行 description) |
| `.pre-commit-config.yaml` | 兜底 | 0 |
| `selftest/` | check.py 自己的回归测试 | 0 |
| `experiments/falsification.md` | 证伪实验,**等真实故障时就地做** | — |
| `DESIGN.md` | 设计推导存档:被推翻的方案和推翻的理由 | — |

## 五、跑法

```bash
python scripts/check.py                # 查 git 改动过的文件(默认)
python scripts/check.py --all          # 全仓库
python scripts/check.py --advise       # 附带「要不要跑 code-simplifier」的判断
python scripts/check.py --report       # 月度复盘:哪条规则该删、哪条该收窄
python scripts/check.py --strict       # 有未豁免命中就 exit 1(CI 用,默认关)
```

误报了就在那行加豁免,**理由是必须写的**:

```python
if "ping" in text:   # check: ignore[keyword-match] 协议探活,不是猜用户意图
```

整个文件豁免用 `# check: ignore-file[规则名] 理由`。

`--report` 看的就是这些豁免。某条规则十天里全靠豁免活着 → 规则错了,删掉它。
**规则应该是长出来的,不是一次设计出来的。**

## 六、6 条检查

| 规则 | 治哪个 | 抓什么 | 只对生产代码 |
|---|---|---|---|
| `keyword-match` | F1 | 对自由文本做关键词/正则判断猜意图 | 否 |
| `fake-success` | F2 | except 里返回假数据、空值、占位 DTO | 是 |
| `prod-mock` | F2 | 生产代码里的 mock / fake / stub | 是 |
| `version-suffix` | F3 | `_v2` / `_legacy` / `_deprecated` 函数名 | 否 |
| `dup-func` | F4 | 结构几乎相同的两个函数(比对 AST,改名骗不过) | 否 |
| `file-too-long` | F3 | 超过 800 行 | 否 |

只查 `.py`。`tests/`、`conftest.py`、`fixtures/`、`repro_*.py`、`debug_*.py` 一律不算生产代码 ——
精确回归测试正需要硬编码具体输入。

## 七、怎么加一个新的失败模式

**照这个顺序走,不要跳到第 4 步。** 大部分坏规则都是从「我觉得这样不好」直接跳到写检查产生的。

1. **先证明它是「模式」不是「个例」。** 至少在**不同任务**里见过 3 次。
   只见过一次的,记在 issue 里等它再犯,别急着立规矩。

2. **写成可判定的判据,不是形容词。**
   ✗「代码要清晰」——无法判定,写了等于没写。
   ✓「失败不得被转换成看似成功的结果;判据是**调用方能否分辨这是真结果还是失败**」。
   写不出判据 = 你还没想清楚这个模式是什么。

3. **用第二节的三问决定放哪一层。** 默认往下沉:
   能静态判定 → 加 check.py 规则;
   只能语义判定 → 进 code-simplifier skill 的清单;
   两者都不行、且模型确实不知道 → 才写进 AGENTS.md。
   **AGENTS.md 每加一行都是每轮付费,加之前先问「能不能下沉」。**

4. **加检查就必须同时加邻近反例。**
   在 `selftest/sample_hits.py` 里,上半部分加**应该命中**的写法,
   下半部分「不应该命中」分隔线之后加**长得像但不该报**的写法。
   反例比正例重要 —— `selftest/run.py` 会断言分隔线之后**零命中**。

5. **在真实仓库上量误报率。**
   ```bash
   python scripts/check.py --all --no-log   # 在你自己的项目上跑
   ```
   **只在自己写的样本上测 = 循环论证** —— 样本是为了让它命中才写的。
   误报率超过三成就别上,它会教会你忽略整个工具。

6. **更新第一节和第三节的表。** 新 F 编号 + 落点。挂不上编号的检查,删掉。

7. **一个月后 `--report` 复查。** 从没命中过 → 删。全靠豁免活着 → 规则写错了,删或收窄。

8. **删规则时,把理由写进 [DESIGN.md](DESIGN.md),不要只删。**
   否则半年后你会因为同一个理由把它再加回来一遍。
   那份文档的全部价值就是记住**哪些方案被否掉了、为什么否** ——
   它用 ⚠️ 保留原文并标注推翻理由,不直接改写,照这个格式续写。

**误伤就缩范围,不降强度。** 一条规则老误报,正确做法是把它的适用范围切小
(只对生产代码、只对自然语言字面量),**不是**把措辞从「禁止」改成「尽量避免」——
后者会让整份文件的所有条款都贬值。

## 八、实测证据

**这套东西唯一的正当留存理由:量过,不是拍的。**

在两个真实的生产仓库(共 611 个 py 文件,记为仓库 A / 仓库 B)上实跑,按误报率砍了两条规则(2026-07-31)。

| 规则 | 结局 | 实测证据 |
|---|---|---|
| `hardcoded-id` | **删除** | 前缀表里 `run_`/`user_`/`task_`/`org_` 是常见英文词缀,结果它在报普通字段名(`"user_confirmed"`、`"run_capability"`)。收窄到只认 UUID / 长 hex 之后,611 个文件里只剩 1 条,还是个 git SHA —— 47 个误报或 1 个无用命中,都不值得留 |
| `prompt-case-patch` | **删除** | 分不清**选项标签**(`关联到"启动SEO全局检测"这几个选项`)、**few-shot 示例**(`例如:"女装"、"iphone壳"`)、**输出模板**(`格式为:"好的,AI帮你定制了…"`)和真正的逐条堆砌 —— 这四者的区别是语义的。而且它本身就是「对自然语言做正则匹配猜意图」,正是它自己要禁的那件事 |

两条规则删掉,但**对应的 AGENTS.md 禁令保留** —— 原则是对的,只是静态脚本判不了,交给 skill + diff review。

同一轮修好的三处:

| 修复 | 效果 |
|---|---|
| `keyword-match` 的字面量必须像自然语言(不是字段名/枚举值) | 113 → 15,砍 86%。`if "text" in cur_content_tmp` 是查 dict 键,不是搜关键词 |
| `keyword-match` 的正则模式必须是字面量且含实际词汇 | 46 → 17。`re.findall(r"\{[^{}]*\}", response)` 是抽 JSON,不是猜意图 |
| `version-suffix` 去掉 `copy\|backup\|orig\|tmp\|temp` | 12 → 10。那几个是普通英文词,把 `_json_safe_copy` 也报了 |

总量:仓库 A 155 → **83**,仓库 B 870 → **167**。

**留下的 6 条确实抓到了真东西** —— 手写正则从自由文本抽字段(中英文各一套)、生产路径上三处 `return self._mock_evaluation()`、同一个函数名在两个模块里重复定义还挂着 `# type: ignore[no-redef]`。

## 九、已知的洞(**这些是设计结论,不是待办**)

1. **静态检查抓不到 F1。**
   codex 实测过:真正的单 case 补丁(`if "退款" in query`,1 个分支)零报警,
   而合法的 13 分支协议解析器被 `C901` 拦下。该抓的抓不到,不该抓的抓了。
   `SIM116` 更糟 —— 它建议把 if 链改成字典,而字典正是特例最好的藏身处,所以已经进了 `ignore`。

   **真正防 F1 的是第二节的验证层:变体 + 邻近反例。**
   `check.py` 全绿不是「修了根因」的证据,只是「没留下明显痕迹」。

2. **迁到 prompt 不算逃逸。**
   判据不是「代码 vs prompt」,是**这个机制会不会泛化**:`if "退款" in query` 换个说法就漏;
   prompt 里写「用户想退款就调 refund」由 LLM 执行,变体都覆盖得到 —— 那是**修好了**,不是藏起来。
   向量 / 语义召回同理。
   只有**逐条粘用户原话**是同一个病换了载体,而那个已经证明静态判不了(见第八节)。

3. **`keyword-match` 的召回缺口:** `if "refund" in query` 这种纯英文单词抓不到 ——
   它和 `if "text" in some_dict` 静态上完全一样。中文和带空格的短语能抓到。
   参数叫 `q` / `s` / `inp` 时也抓不到 —— 把这些短名字加进词表会误伤队列变量和状态字符串,不划算。

4. **`dup-func` 只在本次检查的文件之间比对。** 跨全仓库要 `--all`,函数超过 600 个会跳过。

5. **code-simplifier 是同一个 agent 在同一上下文里自查(F9)。**
   它已经相信自己找到根因时,清单不会提供外部视角 —— 会自然地把新增分支解释成
   「真实的不同情况」。所以 skill 里把**经验验证(跑变体和反例)放在了清单前面**,
   清单只是补充。

   **2026-08-03 补了一半**:AGENTS.md 加了「验证者不该是开发者本人」,高风险改动派干净
   上下文的 subagent 来验。剩下的一半补不上 —— **同一个模型、同样的先验**。
   干净上下文去掉的是路径依赖和沉没成本,去不掉模型共有的偏见。
   而且「有没有真的派」这件事本身不可验证,只能靠模型自觉,所以这条规则的强度天然弱于
   有 hook 兜着的那些。

6. **pre-commit + CI 不是保险。** `--no-verify` 能跳过;而且它只拦得住检查器认识的模式,
   证明不了模型没改坏测试(F6)、没伪造验证结论。

7. **不要抄别人的 CLAUDE.md,包括这一份。**
   抄来的规则你不会去检查它有没有被执行 —— 而写了不检查的规则,
   会让模型学到「这个文件里的规则可以不遵守」,连带削弱整份文件的权重。
   **留着不检查的规则,比没有规则更糟。**
   这里每条都对应一个实际踩过的坑,而且都配了检查手段;换个人用,先按第七节重走一遍。

## 十、需要确认的三件事

1. **`required-version`** —— `pyproject.ruff.toml` 里填的是 `0.12.0` 占位。
   跑 `ruff --version` 换成实际装的版本。**必须固定**,ruff 规则行为会随版本漂移。

2. **代码注释和 commit message 的语言** —— `AGENTS.md` 里现在写的是
   「代码注释、commit message 用英文,文档和对话用中文」。

3. **Stop hook 会拦一次。** 有警告或触发 code-simplifier 条件时返回 `decision: block`,
   模型多跑一轮来处理。靠 `stop_hook_active` 保证只拦一次,不会死循环。
   嫌烦就设 `CHECK_STOP_BLOCK=0`,或删掉对应平台配置里的 Stop 段。

**Codex 的 hook 和 subagent 都已核实**(codex-cli 0.146.0,2026-08-03 实测):

- **hooks —— stable 且默认启用**。事件名和 Claude Code 完全一致:`PreToolUse` / `PostToolUse` /
  `Stop` / `SubagentStart` / `SubagentStop` / `SessionStart` / `SessionEnd` / `UserPromptSubmit` /
  `PreCompact` / `PostCompact` / `PermissionRequest`。契约也一致(`exit 2` + stderr 反馈、
  `decision: block` + reason)。本仓库通过项目级 `.codex/hooks.json` 接线;首次加载或定义变化后,
  需要在 `/hooks` 中审查并信任。Codex 的 `apply_patch` 载荷不提供 `file_path`,检查器会从
  补丁协议的文件头提取本次实际改动的 Python 文件。
- **subagent —— `collaboration.spawn_agent`**,配套 `wait_agent` / `list_agents` /
  `send_message` / `interrupt_agent`,需要 `features.multi_agent = true`。

所以 F9 那条 AGENTS.md 规则两个平台都能真正执行,不是只对 Claude Code 有效。

## 十一、下一步:铺进项目,等一个真实故障

**规则可以铺进项目用了。但要清楚它现在处于什么状态。**

`experiments/falsification.md` 那个证伪实验**还没跑**(2026-08-03 决定:等真实故障)。
它判定的是第二节的核心假设 —— 三层全绿的一份修复,是真的泛化了,还是只是把特例藏得更好了。

不预先造样本跑,是因为**造出来的例子会照着规则的形状造,变成自证**;
实验第一步自己写着「选一个真实故障(不要造)」。等真实故障是照它本意执行,不是拖延。

**代价**:在跑完之前,这套规则是「没被证伪过」,不是「验证过」。
`check.py` 全绿只能当"没留下明显痕迹"。

**触发时刻**(详见那份文档,**在动手修之前**):

- 有人报「这个输入处理错了 / 这句话路由错了」,而你预感修法是加一个判断
- 你正准备写 `if "..." in query`、往 `INTENT_MAP` 加一个 key、或往 prompt 里粘一句用户原话
- 线上来了一个 case,你说不出它属于哪一类

**边际成本几乎为零** —— AGENTS.md 本来就要求每次修 bug 准备变体 + 邻近反例。
多出来的只是:**在让 AI 动手前**先写下你自己那套 cases 并且**不给它**,跑完记个结果。
你那套是独立对照组;它自己造的变体全过、你藏的那套挂了,就是最有信息量的结果。

样本量 1 能证伪不能证明,所以这个实验**不是一次性的** —— 每遇到一个就再跑一次,攒样本。
